PROJECT: Bazarr AutoTranslate
PURPOSE: Translate Bazarr-managed subtitle sidecars through Lingarr with validation, retry recovery, maintenance, status monitoring, and audited manual actions.
STACK: Python 3.11, SQLite v16, requests, lingua-language-detector, vanilla HTML/CSS/JavaScript, Docker
DEPLOY: bazarr-autotranslate container, typically alongside Lingarr on TrueNAS SCALE

STRUCTURE:
docker/autotranslate/app.py - sole production composition entry
docker/autotranslate/production.py, composition.py, initialization.py - resource host, injected dependency namespace, and startup state
docker/autotranslate/services/ - Bazarr, Lingarr, HTTP, and service workflow adapters
docker/autotranslate/scheduling/ - cycle, capacity, retry, repair, circuit, lock, and executor coordination
docker/autotranslate/subtitles/ - parsing, classification, validation, recovery, repair, and subtitle workflow
docker/autotranslate/subtitles/sources.py - SubExtractorr receipt validation, embedded-source preparation, rolling-cue deduplication, and canonical target naming
docker/autotranslate/maintenance/ - retention, library scan, and pruning workflow
docker/autotranslate/manual_review/ - review service, sanitized DTOs, repository protocol, and runtime adapter
docker/autotranslate/persistence/ - SQLite v16 schema, migrations, transaction owner, and focused repositories
docker/autotranslate/status/ - privacy facade, tracker, HTTP server, logging, and status workflow
docker/static/ - Status, Manual review, and Logs frontend assets
tests/ - unittest unit, integration, architecture, migration, shutdown, API, and frontend assertions

ENTRY POINTS:
/app/entrypoint.sh -> python3 -u /app/Bazarr_AutoTranslate.py -> autotranslate.app.main
docker/clean_et_subs.py -> autotranslate.subtitles.library.main

KNOWN QUIRKS:
- Schema v16 is not rollback-compatible; back up SQLite and migrate pre-SQLite state with the preceding release first.
- Bazarr scan delivery is at-least-once because Bazarr exposes no idempotency key.
- Top-level Python files are executable only; historical imports and monkey-patching are unsupported.
- Receipt-backed embedded sources use the fixed `<video>.extracted.json` schema v1 contract and are always preferred over Bazarr sources when valid.
