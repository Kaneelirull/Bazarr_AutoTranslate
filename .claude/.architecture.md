# Parallel maintenance analysis

Status: accepted on 2026-09-01.

Maintenance keeps one lifecycle coordinator. A full cleanup constructs one deterministic `MaintenanceInventory` inside `autotranslate.maintenance`: filesystem directories are enumerated once, overlapping roots are deduplicated, and exact longest-stem ownership groups videos with their sidecars. Undersized detection, target discovery, validation, source pairing, pending-repair checks, and pruning consume that inventory. Incremental pruning builds the same contract from only the requested videos and inventories each affected parent once.

The coordinator maintains a bounded queue of at most twice `MAINTENANCE_WORKERS` and consumes process results in submission order. Spawned workers receive serializable paths and policy values and return analysis DTOs only. Before subtitle validation, the coordinator batch-probes every uncached `(normalized video path, size, modified time)` once. The run-level duration map injects either the known duration or an explicit unavailable result into every dependent validation, so validation and pruning never repeat `ffprobe` during that run.

The queue bound covers both running futures and completed out-of-order results. Shutdown uses the process-wide remaining grace period, cancels queued work, and terminates child processes that exceed the deadline.

Workers may parse SRT files, hash content, run language/structure/completeness validation, call bounded `ffprobe`, and count cues. They must not import the production runtime, write SQLite or status, mutate subtitle files, call Bazarr/Lingarr, or perform AI repair.

Before applying a result, the coordinator compares the worker's target stat/hash with the current file and falls back or defers when identity changed. Cleanup actions also recheck the expected hash under the artifact lock. This keeps process-level parallelism from creating time-of-check/time-of-use mutations.

Schema v17 stores stable maintenance outcomes keyed by normalized target path. A hit requires unchanged target size/mtime, exact source/video/receipt metadata, validator version, maintenance-policy fingerprint, and a stable prior action. Cache JSON details also carry `mediaDurationSeconds` and target-only `pruneEvidence`; no schema migration is required. Current cache evidence is materialized into the run-level analysis maps. A legacy hit without those optional details receives one targeted analysis and is backfilled by the coordinator. Cache misses are analyzed normally; cache writes occur in a coordinator-owned batch after pruning.

Pruning receives the shared inventory, duration map, validation results, and cache evidence directly. It performs no blanket second validation pass. Every mutation remains coordinator-owned and preserves readiness policy, dry-run/report behavior, artifact locks, current-file stat/hash checks, quarantine/deletion safeguards, cancellation, and bounded shutdown. An unavailable duration is recorded once for the run and safely defers all pruning decisions for that video.

Maintenance status remains an additive read contract. The coordinator publishes `inventory`, `probing`, `validation`, and `pruning` stages with stage-local counters, progress, and ETA while retaining legacy `files*` fields. Inventory is indeterminate until enumeration completes; estimated total is never below elapsed time. The dashboard prefers stage counters and falls back to legacy file or cue progress.

Existing hash-valid records seed the metadata cache during their first v17 scan. Cache rows age out through normal state retention so deleted or long-unseen paths cannot grow the database indefinitely.

## Trusted embedded target promotion

`subtitles.sources` discovers only extraction-receipt tracks whose media identity,
track metadata, accepted hash, language alias, and variant still match. Before
translation source selection, `items_workflow` may promote the best non-forced
track already in a missing managed language. `maintenance.runtime` runs the same
adoption contract before validation and pruning so a newer embedded track can
supersede a Lingarr-owned canonical sidecar.

Receipt media identity requires exact case-insensitive filename and byte size.
Modification time permits at most one microsecond of cross-filesystem precision
loss; larger changes invalidate the complete receipt. Every selected track still
requires an accepted receipt hash match.

Embedded targets use target-only structure/language and media-duration checks,
plus English-relative temporal coverage. Independent subtitle segmentation is
allowed: at least 90% of English cue midpoints must fall within a target interval
expanded by two seconds. The English reference preference is receipt-backed same
variant, receipt-backed plain English, then a canonical English sidecar with the
same preference.

`subtitles.workflow` owns publication under artifact locks and the approval
guard. It copies through the retained-candidate publication journal and never
rewrites the receipt-owned extract. Unknown canonical files are preserved;
replacement requires matching `lingarr` or `embedded` artifact provenance.
Successful records use `origin=embedded`, `operation=embedded_promotion`, and
`validationMode=embedded-reference`, including receipt and reference evidence.
Maintenance revalidates that evidence before counting the language ready for
pruning. Receipt-unowned `extracted.<language>.srt` files require an exact durable
submission path/hash match to be treated as recoverable provider output;
otherwise they remain unknown and retained by default.

## Recovery and name review (schema v18)

Subtitle recovery retains the existing coordinator/worker boundary. `subtitles.names` owns pure exact matching; `persistence.names` owns scoped decisions, revision snapshots and permanent decision history. Workers receive immutable phrase pairs and revision values. Coordinators reject stale approval-dependent results and include revisions in maintenance-cache dependencies.

`subtitles.publication` owns retained candidates, receipts and same-filesystem staging. `persistence.publications` owns the publication journal and retry schedule; scheduling resumes it without provider calls. Artifact locks precede the approval guard, and source/target identity is checked immediately before replacement. Manual review details expose dialogue through a dedicated endpoint; status/list DTOs continue to carry identifiers and reasons.

Schema v18 is additive. Deployment requires a SQLite backup; rollback restores that backup with the previous image. See `docs/retry-recovery-and-name-review.md` for contracts and recovery behavior.
