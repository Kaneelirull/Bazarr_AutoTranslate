PROJECT PLAN - Parallel CPU maintenance workers
LAST UPDATED: 2026-09-01

GOAL:
Use multiple CPU cores for every suitable non-AI maintenance analysis path without allowing worker processes to mutate files, SQLite, status, or remote services.

BRANCH:
- `codex/parallel-maintenance-workers`, created from freshly fetched `origin/main`.

IMPLEMENTED:
- `MAINTENANCE_WORKERS` defaults to 4 and accepts 1–32.
- A bounded spawned-process pool performs subtitle parsing, hashes, language validation, completeness checks, pruning readiness preflight, and startup retry cue counting.
- The coordinator enumerates files, submits immutable tasks, consumes results in discovery order, rechecks target identity, and exclusively owns database writes, status, quarantine/deletion, Bazarr calls, and AI repair.
- Existing-library validation caches stable outcomes using target size/mtime, source/video/receipt metadata, validator version, and maintenance configuration fingerprint.
- Schema v17 adds `maintenance_validation_cache`; cache writes are batched and stale/changed inputs are recomputed safely.
- Maintenance status reports worker count, cache hits, submitted/completed tasks, and worker failures.
- The bounded queue counts running and completed out-of-order work, and shutdown terminates child processes that exceed the shared grace deadline.
- Existing hash-valid rows seed the cache after upgrade; normal retention removes cache entries that have not been seen within the configured state window.

VERIFICATION:
- Python compile and full discovery pass locally: 323 tests with one expected Windows symlink-permission skip.
- Frontend strict typecheck, all 19 Vitest tests, and the production build pass.
- Docker Compose configuration validation passes with placeholder review values.
- The production image builds successfully, and all six maintenance worker/cache lifecycle tests pass inside its Python 3.11 runtime.
- Tests cover default/bounded configuration, non-contiguous ordered worker results, real process isolation, cache round-trip/deletion, cache hits on unchanged scans, pruning compatibility, and undersized cleanup behavior.
