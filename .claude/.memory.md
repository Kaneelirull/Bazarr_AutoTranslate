PROJECT PLAN - Bazarr AutoTranslate React UI migration
LAST UPDATED: 2026-08-18

GOAL:
Replace the three production vanilla-JavaScript interfaces with a React 19 + TypeScript + Vite multi-page frontend while preserving the existing Python HTTP/API contracts, Kaneel visual language, URLs, CSP, responsive behavior, accessibility, and Docker runtime.

SUCCESS CRITERIA:
- `/`, `/review`, and `/logs` are rendered by production React entry points built during the Docker image build.
- No legacy page renderer remains on a migrated production path.
- Existing API payloads, manual-action safeguards, polling cadence, timezone behavior, privacy guarantees, and theme preference remain compatible.
- Keyboard focus, expanded-state persistence, loading, empty, error, stale-data, disabled, success, destructive-action, and narrow-width behavior are covered by behavioral tests.
- Dark and light themes match the existing Kaneel token system without duplicate theme components or avoidable hardcoded component colors.
- Python tests, TypeScript checks, frontend tests, production build, Docker build/smoke test, and final code review pass before publication.

CONSTRAINTS AND ASSUMPTIONS:
- Preserve the current UI design and information architecture; this is an architecture migration, not a redesign.
- Keep the Python standard-library HTTP server and same-origin relative API routes.
- Use a Vite multi-page build rather than introducing client-side routing.
- Configure deterministic asset names so the Python server and strict CSP can serve the build without unsafe inline scripts or styles.
- Keep Node and development dependencies out of the final runtime image via a multi-stage Docker build.
- The branch is stacked on `codex/recover-multi-quarantine-subtitles` at `8154ae4`; its three commits must be present in the eventual PR base or explicitly included in the PR.
- Existing untracked files under `examples/MissingRepair/` are user-owned and excluded from commits.
- GitHub CLI authentication must be renewed before push and draft-PR creation.

DECISIONS:
- Use React 19, TypeScript, and Vite because the UI now has cross-page shared behavior, polling, complex local state, and fragile full-DOM rerenders.
- Use three Vite page entries and preserve server URLs rather than add a client router.
- Migrate logs, then manual review, then dashboard to validate the build path before the highest-complexity screen.
- Preserve the current Kaneel UI and CSS tokens; defer optional information-density redesign until after architecture parity.
- Keep the Python API and security boundaries unchanged.
- Use `upgrade/migrate-ui-to-react` as the local migration branch.

ROLLBACK:
- Each page migration is a focused commit and can be reverted independently before merge.
- The runtime continues to be a single Python container; rollback is the preceding Docker image/commit with the vanilla assets.
- No database, API, or persisted-state migration is planned.
