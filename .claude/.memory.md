PROJECT PLAN - Simplify and harden the operator UI
LAST UPDATED: 2026-08-18

GOAL:
Make Status, Manual Review, and Logs simpler and more responsive without changing URLs, API payloads, polling intervals, security boundaries, themes, or manual-action safeguards.

BRANCH:
- `upgrade/simplify-operator-ui`, created from freshly fetched `origin/main`.
- The React migration was already merged into `origin/main` as PR #46, so no duplicate cherry-pick was needed.
- User-owned untracked files under `examples/MissingRepair/` remain excluded.

IMPLEMENTED:
- Standardized the page shell at 1280px, panel bodies at 24px desktop/16px mobile, 44px mobile controls, contained table overflow, and consolidated mobile card-table rules.
- Consolidated Status into Overview, Work, and Health & history.
- Added Recent to Work by merging translation and maintenance outcomes newest-first; Auto prioritizes Active, Retry, Up next, then Recent.
- Removed the recovery-attention strip; retry counts live in the Work selector and Manual Review count remains in global navigation.
- Added an accessible Health & history disclosure with Health, Observations, and History tabs; it opens and closes as attention appears or clears.
- History selects Outcomes or Maintenance and one window: 1h, 6h, 12h, 24h, or 7d.
- Replaced Manual Review cards with a compact summary and moved secondary mobile filters behind an accessible More filters control; Logs and Observations use the same pattern.
- Split Manual Review request state into initial, foreground, background, and mutation states. Background polling leaves controls active; mutations stay single-flight through the protected refresh.
- Preserved tab/filter/expanded state and added keyboard tab navigation.
- Added Playwright Chromium visual regression coverage for Status healthy/warning, Manual Review, and Logs in dark/light at 1600x1000 and 390x844, with Linux and Windows baselines separated to account for OS text rasterization.
